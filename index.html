Quick start

Clone it. Inspect it. Run it locally.

Start with the repository source and a development environment. The scaffold requires a real token issuer configuration; its example values are nonfunctional placeholders. It never queries a Microsoft tenant.

Step 01 · Prerequisites & download

Get the source

Install Git and Node.js 24 or later, then clone the public repository. Alternatively download the source archive.

git clone https://github.com/skunkworks-africa/skunkworks-365-mcp.git
cd skunkworks-365-mcp
npm install --ignore-scripts
Download ZIP instead ↗
Step 02 · Local configuration

Configure authentication

Copy the example environment and registry, then replace placeholder issuer, audience, JWKS URL and verified subject. Keep real values outside version control.

cp .env.example .env
cp access-registry.example.json access-registry.json

Use set -a; . ./.env; set +a in a Unix shell to load settings, or your OS equivalent. Do not expose the server publicly.

Step 03 · Build & validate

Run the prototype

Compile the TypeScript project, run the included tests and start the locally bound service after populating valid authentication settings.

npm run build
npm test
npm start

The local endpoint is http://127.0.0.1:3000/mcp. It requires a signed bearer token from your configured issuer.

Step 04 · Review before production

Understand the boundaries

All seven Microsoft/provider reads currently return connector_unavailable. Remote OAuth discovery, Graph adapters, distributor billing and production hardening are still on the roadmap.

Review security checklist →

Do not paste tenant credentials, access tokens or customer billing data into public GitHub issues.

Connect your AI client

Ready for ChatGPT—once the remote endpoint is deployed.

The source targets MCP interoperability. ChatGPT cannot connect directly to a local-only HTTP service, and this documentation domain is not the MCP endpoint. Follow these steps only after the project has a separately hosted, authenticated HTTPS runtime.

Remote service not deployed

ChatGPT setup

  1. Open ChatGPT on the web and go to Plugins.
  2. Choose + → Add custom MCP server (subject to workspace permissions).
  3. Enter your deployed HTTPS MCP endpoint (typically ending in /mcp), not this documentation website.
  4. Configure OAuth if required; review the server's permissions and risk warning.
  5. Create/install the plugin, inspect discovered tools and test only an authorized tenant.

Frequently asked questions

The important distinctions.

Is the public MCP server online?

No. This site hosts public documentation. The present prototype binds to localhost and has no live upstream adapters. A secured remote service must be deployed separately before ChatGPT can connect.

Can I manage CSP billing today?

Not yet. Billing, distributor reconciliation and Microsoft Graph integrations are planned. The local billing tool intentionally returns a connector-unavailable response.

Does this work for indirect resellers?

The project is designed to accommodate reseller-specific data paths, but Microsoft does not offer Partner Center API access to indirect resellers. Authorized distributor APIs or exports are needed for that commercial data.

Is Microsoft customer data public?

No. The repository and docs are public, but production tenant identifiers, access tokens, customer records and billing data must stay private and server-side.
